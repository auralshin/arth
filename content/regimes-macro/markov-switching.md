### Markov Switching Models

> info **Metadata** Level: Advanced | Prerequisites: Market Regimes, Probability, Maximum Likelihood | Tags: regimes, markov-switching, transition-matrix, hamilton-filter, persistence

A **Markov switching model** makes the regime idea precise. The observed series is generated by one of `K` parameter sets, and the choice of which set is active follows a Markov chain: the probability of next period's state depends only on this period's state, not on how long the market has been there or on how it arrived. That single assumption buys an enormous amount — it makes the model estimable by maximum likelihood, gives a closed-form expected duration for each regime, and produces a probability of being in each state at every date rather than a hard label.

The model's value is less in prediction than in description. It tells you how persistent each state is, how different the parameters really are, and how confidently the current state can be identified from the data you have. Those three numbers are usually more useful than any signal derived from the model, and they are the honest starting point for asking whether a regime framework is worth the complexity at all.

---

#### Formal Definition

A `K`-state Markov switching model for a return series is:

```text
r_t | (s_t = k)  ~  Normal(mu_k, sigma_k^2)

P(s_t = j | s_(t-1) = i) = p_ij
```

where:

- `r_t` is the return at time `t`
- `s_t` is the latent state at time `t`, in `{1, ..., K}`
- `mu_k`, `sigma_k` are the mean and volatility of state `k`
- `p_ij` is the probability of moving from state `i` to state `j` in one period

The `p_ij` collect into a **transition matrix** `P`, a `K x K` array whose rows each sum to 1. Row `i` is the full distribution of where you go next, given that you are in state `i` now.

Two derived quantities carry most of the interpretation:

```text
E[duration in state k] = 1 / (1 - p_kk)

pi = pi P,  with sum(pi) = 1          (the stationary distribution)
```

The stationary distribution `pi` gives the long-run share of time spent in each state. For a two-state chain it can be read straight off the durations: the share of time in state `k` is its expected duration divided by the sum of both durations.

> info **The Markov property is the load-bearing assumption** It says the chain has no memory beyond the current state. Real regimes often show duration dependence — a stress episode that has lasted three months may have a different exit probability than one that started yesterday. Semi-Markov models relax this at the cost of tractability.

#### Worked Example: Reading a Transition Matrix

Suppose a two-state model has been fitted to daily returns and produced this transition matrix, with state 1 calm and state 2 stressed:

<table>
  <tbody>
    <tr>
      <td><strong>From \ To</strong></td><td><strong>Calm</strong></td><td><strong>Stressed</strong></td>
    </tr>
    <tr>
      <td><strong>Calm</strong></td><td>0.95</td><td>0.05</td>
    </tr>
    <tr>
      <td><strong>Stressed</strong></td><td>0.20</td><td>0.80</td>
    </tr>
  </tbody>
</table>

1. **Rows sum to one.** `0.95 + 0.05 = 1` and `0.20 + 0.80 = 1`. Always check this first; an unconstrained optimiser can drift.
2. **Expected duration of calm.** `1 / (1 - 0.95) = 20` trading days, about a month.
3. **Expected duration of stress.** `1 / (1 - 0.80) = 5` trading days, about a week.
4. **Long-run time share.** Calm gets `20 / (20 + 5) = 0.80`; stress gets `0.20`. Verify against the stationary equation: `0.80 * 0.95 + 0.20 * 0.20 = 0.76 + 0.04 = 0.80`, which reproduces the calm weight, so `pi = (0.80, 0.20)` is correct.
5. **Two steps ahead.** Squaring the matrix gives the two-day transition probabilities:

<table>
  <tbody>
    <tr>
      <td><strong>From \ To (2 days)</strong></td><td><strong>Calm</strong></td><td><strong>Stressed</strong></td>
    </tr>
    <tr>
      <td><strong>Calm</strong></td><td>0.9125</td><td>0.0875</td>
    </tr>
    <tr>
      <td><strong>Stressed</strong></td><td>0.3500</td><td>0.6500</td>
    </tr>
  </tbody>
</table>

Check one entry by hand: from stressed to calm in two days is `0.20 * 0.95 + 0.80 * 0.20 = 0.19 + 0.16 = 0.35`. Either you leave immediately and stay out, or you stay one more day and then leave.

6. **Survival probability.** The chance calm persists uninterrupted for the next 20 trading days is `0.95^20 = 0.358`. Even a state with a 20-day *mean* duration only survives a full 20 days about a third of the time — the geometric distribution is heavily skewed, so most visits are shorter than the mean and a few are much longer.

#### Estimating the Model

The states are unobserved, so the likelihood must integrate over every possible state path. The **Hamilton filter** does this recursively in a single pass, and the same recursion yields the state probabilities as a by-product. For each date:

```text
1. Predict:  xi_pred(j)  = sum over i of  xi_filt_prev(i) * p_ij
2. Weight:   w(j)        = xi_pred(j) * f(r_t | mu_j, sigma_j)
3. Normalise: xi_filt(j) = w(j) / sum over k of w(k)
4. Accumulate: log_lik  += log( sum over k of w(k) )
```

where `f` is the conditional density of the observation under state `j`. Maximising the accumulated log-likelihood over `(mu_k, sigma_k, p_ij)` gives the estimates. The **Expectation-Maximisation (EM)** algorithm is the common alternative: it alternates between computing state probabilities given parameters and re-estimating parameters as probability-weighted averages, and it is more robust to poor starting values than direct optimisation.

Two practical hazards:

- **Label switching.** The likelihood is identical if you swap the state indices. Impose an ordering constraint (for instance, `sigma_1` below `sigma_2`) or the parameters will be uninterpretable across re-fits.
- **Degenerate states.** A state can collapse onto a single observation with `sigma` approaching zero, sending the likelihood to infinity. Bound the variances away from zero.

#### Interpreting the Fit

Before using a fitted model, ask three questions.

**Are the states actually different?** Compare `mu_k` and `sigma_k` across states relative to their standard errors. Two states with overlapping volatility estimates are one state with estimation noise.

**Are the states persistent?** If both diagonal entries are near 0.5, the chain is close to independent coin flips and the "regimes" carry no information about tomorrow. Persistence near 1 in every state is the opposite failure — the model has found a structural break, not a recurring regime.

**How confident is the classification?** If the filtered probabilities hover near `1/K` most of the time, the model cannot tell the states apart from the data given. Plotting the distribution of the maximum filtered probability is a quick diagnostic: a good fit is bimodal near 0 and 1, a poor one is a smear in the middle.

> warning **Persistence is estimated, not known** The diagonal of `P` is the hardest part of the model to pin down, because it is identified only by the number of switches observed. A sample containing four regime changes cannot support confident statements about transition probabilities.

#### In Practice Across Asset Classes

**Equities.** The canonical application: a low-volatility, mildly positive-drift state and a high-volatility, negative-drift state. The estimated stressed state typically has a large negative mean, but that mean is estimated from few observations and should not be treated as a forecast.

**Rates.** Switching is often applied to the level or slope of a curve rather than to returns, and the states line up with policy stances. Because policy changes are announced, some of the switching is observable directly and a model that ignores that is working with less information than you have.

**FX.** Two-state models fit carry-like pairs well, but the stressed state is short and rare, so its parameters are fragile. The transition matrix is frequently more stable across pairs than the state parameters are.

**Commodities.** States often correspond to inventory conditions and show up in curve shape as much as in volatility. A switching model on the front-to-back spread can be more informative than one on spot returns — see [Roll and Carry](/markets/roll-and-carry).

**Credit.** Spread series are persistent and marks are stale, so a switching model tends to over-estimate persistence. Serial correlation in the observation series is being absorbed into the transition matrix.

**On-chain markets.** With few complete cycles, the transition matrix is estimated from a handful of switches. Adding an observable conditioning variable — funding, open interest, leverage — as a covariate on the transition probabilities usually helps more than adding states. See [Open Interest](/signals/open-interest).

#### Assumptions and Failure Modes

- **Markov (memoryless) transitions.** Implies geometric durations. If real regimes have a characteristic length, the geometric assumption misprices both very short and very long visits.
- **Constant transition matrix.** The probability of switching is assumed stable over the whole sample. If it is not, the fitted `P` is an average of incompatible regimes-of-regimes.
- **Conditional normality within a state.** Fat tails inside a state get explained by spurious extra switching. A `t`-distributed emission often reduces the number of states needed.
- **Known number of states.** Likelihood always increases with `K`, and standard likelihood-ratio tests are invalid here because the null sits on a boundary of the parameter space. Information criteria are a rough guide at best.
- **Independent observations given the state.** Autocorrelation in returns leaks into the state estimates, making the filter switch on momentum rather than on regime. See [Autocorrelation](/quant-math/autocorrelation).
- **The sample contains enough switches.** Everything about `P` rests on the count of observed transitions, which is far smaller than the number of observations.
- **In-sample fit is not out-of-sample classification.** Even a well-specified model identifies a switch only after the new state has produced enough evidence to overcome the prior.

#### Code

```python
import numpy as np

def expected_durations(transition_matrix):
    """Mean number of consecutive periods spent in each state."""
    P = np.asarray(transition_matrix, dtype=float)
    assert np.allclose(P.sum(axis=1), 1.0), "rows must be probability vectors"
    return 1.0 / (1.0 - np.diag(P))


def stationary_distribution(transition_matrix):
    """Long-run share of time in each state: the left eigenvector for eigenvalue 1."""
    P = np.asarray(transition_matrix, dtype=float)
    values, vectors = np.linalg.eig(P.T)
    target = np.argmin(np.abs(values - 1.0))
    pi = np.real(vectors[:, target])
    return pi / pi.sum()


def hamilton_filter(returns, means, vols, transition_matrix):
    """Filtered state probabilities and log-likelihood, one causal pass.

    Only past and present observations enter each row of the output,
    which is what makes it usable in a live setting.
    """
    P = np.asarray(transition_matrix, dtype=float)
    means, vols = np.asarray(means), np.asarray(vols)
    n_states = P.shape[0]
    xi = stationary_distribution(P)          # start from the ergodic prior
    filtered = np.empty((len(returns), n_states))
    log_lik = 0.0
    for t, r in enumerate(returns):
        predicted = xi @ P
        density = np.exp(-0.5 * ((r - means) / vols) ** 2) / (vols * np.sqrt(2 * np.pi))
        weighted = predicted * density
        evidence = weighted.sum()
        xi = weighted / evidence
        filtered[t] = xi
        log_lik += np.log(evidence)
    return filtered, log_lik
```
